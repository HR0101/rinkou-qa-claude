# 輪講の発表準備ノートを作る（軽量版：質問と逆質問）

このスキルは `rinkou-qa` の軽量版です．**式の解説・図の解説・用語解説などの解説部分を省略**し，輪講本番で即座に役立つ**「発表者への質問」**と**「司会から来る逆質問への答え」**の作成に特化します．

| 作るもの | 中身 | 読むもの |
|---|---|---|
| ほかの人の回の**質問** | 考えて答える質問，レベル1〜5の質問（意図・言い換え付き），表記の指摘，使い分け | [references/peer-questions.md](references/peer-questions.md) |
| ほかの人の回の**逆質問** | 最優先の表，難易度別の索引，分類ごとの全問，一問一答，詰まったときの返し方 | このファイルの「逆質問の作り方」 |
| **回のメモ** | 資料とノートへのリンク，聞いた質問，当日のメモ | [templates/session-memo.md](templates/session-memo.md) |

表：軽量版で作るノートと参照ファイル．

## 呼び出し方とファイルの受け取り

`/rinkou-qa-light` と呼んでから，次のメッセージで資料（PDF）を添付する使い方を想定している．呼び出しと同じメッセージに添付や指示があってもよい．

1. **対象がまだないとき**（指示も添付もない）：作業を始めない．作れるノートを2〜3行で示し，資料（PDF，tex）を添付するよう頼んで待つ．
2. **添付を受け取ったら**，ファイル名と中身から作成するノートを決める．
   - ほかの人の名前が入った資料 → 質問ファイル（`{範囲}_{名+姓}_質問.md`），逆質問ファイル（`{範囲}_{名+姓}_逆質問.md`），回のメモ（`第N回輪講_M_D.md`）．
   - 先に，ユーザーの運用ルール（メモリ，運用ルールのノート，親ノートの一覧）を読む．
   - 人の名前をファイル名のローマ字から推測せず，親ノートやメモリで確かめる．
3. **書き始める前に作成対象を選択肢で確認する**：
   - ユーザーの指示に「質問だけ」「逆質問だけ」「両方」と明示されていない場合は，**ファイルを作成する前に，必ず次の選択肢を提示してユーザーの選択を待つ**：
     ```text
     作成するノートを選択してください：
     1. 両方作成（質問ノート ＋ 逆質問ノート）
     2. 発表者への質問ノートのみ（{範囲}_{名+姓}_質問.md）
     3. 逆質問ノートのみ（{範囲}_{名+姓}_逆質問.md）
     番号（1〜3）またはご希望を入力してください．
     ```
   - ユーザーから返答（1〜3，または「両方」「質問だけ」など）を受け取ってから作成を開始する．
   - 最初から「質問だけ作って」「逆質問だけ作って」「両方作って」と指定されている場合は，確認を挟まずに即座に作成を開始してよい．
4. **添付の届き方**：パスがあればスクリプトに渡し，中身だけなら一時ファイルに保存して処理する．

## 共通の決まり

- **解説（式の解説・図の解説・用語解説）は作らない**．解説の網羅に時間を使わず，質問と逆質問の質を研ぎ澄ます．
- **原著と照合し，数値は検算する**．式の意味を調べ，図を見て気づいたこと（概略図と式の不整合など）も質問に活かす．
- **質問は少なすぎないようにする**．資料のページ数と式・図の数から決まる問数の目安（下の「問数の目安」）に届くまで，触れていない文・式・図・記号・数値を探して足す．
- **数より質**．問数の目安は下限として守るが，それ以上に増やすことより，質問一つ一つの品質を上げることを優先する．弱い質問は，数を変えずに強い質問に入れ替える（下の「質問一つ一つの品質」）．
- **難易度を5段階に分ける**．質問・逆質問ともに，下の「難易度の5段階」のレベル1〜5に分け，各レベルを全問の1割以上にする．同じ文・式・図にレベル1〜5の問いを段階を変えて立てると（レベルのはしご），言い換えなしで問数が増える．
- **資料を見れば答えが書いてある質問ばかりにしない（内容の深さ）**．定義，図のラベル，本文の言い換えを聞く質問は確認用にとどめる．質問の中心は**考えて答える質問**にし，資料1ページあたり5問以上作る．質問の頭に，考え方の印 〔組み合わせ〕〔もし〕〔比較〕〔数値〕〔つながり〕〔理由〕〔限界〕〔前提〕 を付ける（[references/checklist.md](references/checklist.md) の「内容の深さ」）．
- **質問の意図と言い換えを用意する**．質問した後に「その質問の意図は何ですか」「どういう意味ですか」と聞き返されたときに備え，発表者に聞く質問には，想定回答の「→」の下に次の2行を付ける．
  - `- 意図：` 何を確かめたいか，なぜ気になったか（資料のどこを読んでそう思ったか），答えが何につながるか．1〜2文．
  - `- 言い換え：` 専門用語を減らし，具体例や数値を入れて短く言い直した質問．「〜という意味です」の形で，そのまま口で言える文にする．
- **答えが「はい」で終わる質問ばかりにしない**．「〜ですね」「〜という理解でよいですか」の確認の質問だけでなく，「何ですか」「なぜですか」「どう違いますか」「いくらですか」「どうなりますか」と答えを説明してもらう質問を，レベル1〜5のどの段にも作り，全体の4割以上にする．
- **冒頭に「本日のベスト3質問」を置く**．本番で即座に使えるよう，スイートスポット（直感・比較・トレードオフ）の3問を抜粋して冒頭に配置し，先生から意図を聞かれたときの防衛用メモ（自分の考え）を付ける．
- **単語検索（Ctrl+F / Cmd+F）に対応する**．質問行に `〔キーワード: 用語, 略称, 記号, 式番号/図番号〕` を明記する．日本語名だけでなく英語略称（ISI, BER, SNR, RC等）や数式記号（$E_b, E_d, \alpha$等），式番号（式(3.73)）を併記し，どんな単語で検索しても1発で該当行にジャンプできるようにする．
- **進行順クイックナビとキーワード逆引き索引を置く**．冒頭（ベスト3直後）に，スライド（ページ）順にトピックとおすすめ質問を引ける「スライド・節別 クイックナビ」と，単語・記号から質問・解説を逆引きできる「キーワード逆引き索引」を配置する．
- **アウトライン（目次）対応の小見出しを使う**．質問セクション内の節区切りには小見出し（`####`）を使い，Obsidian や VS Code のアウトラインパネル（目次）から節単位でワンクリックジャンプできるようにする（check_coverage.py は小見出しがあってもレベルを正しく判定する）．
- **ユーザーがノートに書き込んだメモ**（添削，「逆質問」，聞かれそうなこと）は消さずに残し，内容を反映する．

## 参照ファイルとスクリプトの場所

- `references/`：作り方（[peer-questions.md](references/peer-questions.md)，[checklist.md](references/checklist.md)，[real-questions.md](references/real-questions.md)，[source-format.md](references/source-format.md)）
- `templates/`：ノートのひな形（[peer-questions.md](templates/peer-questions.md)，[peer-reverse-qa_source.txt](templates/peer-reverse-qa_source.txt)，[session-memo.md](templates/session-memo.md)）
- `scripts/build_qa.py`：元データから「## 想定質問」節を組み立てて差し替える．元データの先頭に `%levels 5` と書くと5段階の索引を作る
- `scripts/check_coverage.py`：`--qa` で問数とレベルの配分が目安に届いているか，`--sentences` で資料の文の一覧（手順，理由なし，命名，仮定，評価語，列挙の印）を出す．`--quality` で点検候補を出す
- `examples/`：想定質問の元データの実例（[Kadai20261013_source.txt](examples/Kadai20261013_source.txt)）

## 逆質問の作り方

自分が質問しなかったときに司会から飛んでくる内容理解の質問に答えるため，逆質問ファイルに想定質問と答えを入れる．

1. **読む**：対象の資料（tex と PDF）．必要なら原著も見る．
2. **洗い出す**：[references/checklist.md](references/checklist.md) の観点を当てる．
   - 資料の文を書き出し，**1文に1問以上**を作る．式は1つにつき7問以上，図は1つにつき8問以上．
   - 各問に**レベル1〜5**を付ける．
   - **考えて答える質問**：頭に 〔組み合わせ〕〔もし〕〔比較〕〔数値〕〔つながり〕〔理由〕〔限界〕〔前提〕 を付ける．
   - **実際に来た型**（[references/real-questions.md](references/real-questions.md)）：命名，前提，評価語，違い（記号・物理量），列挙に加え，式番号指定による式の形の理由，図の演算・素子数の理由，複数図の比較などの型で問いを立てる．
   - 文の書き出し：
     ```bash
     python3 -I scripts/check_coverage.py 資料.pdf 質問.md --sentences
     ```
3. **元データを書く**：作業用の一時ディレクトリに元データ（`.txt`）を作る．書式は [references/source-format.md](references/source-format.md)．[templates/peer-reverse-qa_source.txt](templates/peer-reverse-qa_source.txt) から始める．先頭に `%levels 5` を書く．
4. **検算**：新しく書いた式と数値は検算する．
5. **組み立てる**：
   ```bash
   python3 -I scripts/build_qa.py 元データ.txt 逆質問ノート.md --dry-run
   python3 -I scripts/build_qa.py 元データ.txt 逆質問ノート.md
   ```
6. **確かめる**：
   ```bash
   python3 -I scripts/check_coverage.py 資料.pdf 逆質問ノート.md --qa 元データ.txt --min-deep-per-page 5 --quality
   ```

## 質問一つ一つの品質

| 点検すること | 満たしていないときの直し方 |
|---|---|
| 指す所が1つに決まる（ページ・式・図・文） | 【ページ，場所】と式・図の番号で指す |
| 一問一義（1つのことだけ聞く） | 二つ聞いていたら，大事な方だけにするか2問に分ける |
| 短く一回で伝わる（本文90字以内，資料の訳語） | 前置きを削り，引用は【】に移す |
| 答えに価値がある（答えると理解が確かめられる） | 年号や個数を聞くだけの質問は，条件を変える・組み合わせる質問にする |
| 前提が正しい（引用・数値・式を検算済み） | 計算し直す．原著の誤りは原著の話として聞く |
| 答えが資料と計算で確かめられる | 意見や好みを聞かない |
| 重複しない（同じ答えになる質問は1つ） | 1つにまとめ，空いた枠を触れていない所の質問にする |
| 相手が答えられる（資料と前の節の知識で） | 範囲外は少数にとどめ，〔限界〕の印を付ける |
| 答えの質（結論1文 → 根拠のページ・式 → 検算した数値） | 推測は推測と書く |

## 問数の目安

| 作るもの | 目安（下限） | 確かめ方 |
|---|---|---|
| 逆質問（ほかの人の回） | 資料1ページあたり35問，式1つに7問，図1つに8問，各レベル1割以上，考えて答える質問1ページ5問 | `--qa 元データ.txt --min-deep-per-page 5` |
| 発表者への質問 | 資料1ページあたり15問（表記の指摘を含む），式・図それぞれに2問，各レベル1割以上，レベル1〜2で2割以上，答えを説明してもらう質問4割以上，考えて答える質問1ページ5問，全問に意図と言い換え | `--qa 質問.md --min-per-page 15 --min-per-equation 2 --min-per-figure 2 --min-easy-share 0.2 --min-open-share 0.4 --min-deep-per-page 5 --require-intent` |

## 難易度の5段階

| レベル | 名前 | どんな質問か | 例 |
|---|---|---|---|
| 1 | 超基礎（言葉の確認） | 語や記号の意味，どこに書いてあるか．「はい」か一言で答える | 「量子化雑音とは，丸めたときのずれのことですね」 |
| 2 | 基礎（読み取り） | 図の要素・軸，式の記号を読む，文を言い換える | 「図2.16 の左端の列は，1.3 V が 1.5 V になり符号番号5 になる流れですね」 |
| 3 | 標準（理由） | なぜそうなるか，式や図が何を言っているか | 「なぜ信号電力を上げても符号間干渉は改善しないのですか」 |
| 4 | 応用（式・数値・つながり） | 導き方，数値の計算，他の節や前の担当とのつながり，条件を変えたら | 「1ビット増やすと SNR は何 dB 上がりますか」 |
| 5 | 発展（範囲外・反論・誤り） | 資料の範囲外，反例，境界，原著の誤り | 「式(2.19) の $q(L-1)$ は図2.15 の $V_{pp}=Lq$ と合っていますか」 |
