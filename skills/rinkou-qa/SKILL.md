# 輪講の想定質問をできる限り詰める

発表原稿や課題原稿の「## 想定質問」節に，資料のどこを突かれても詰まらないだけの質問と答えを入れる．
作者の実績は，担当範囲の発表原稿で344問，質疑4問の課題原稿で268問（★59，最優先20）．
自分の発表原稿・課題原稿では，想定質問だけの別ノートは作らず，原稿ノートの節にまとめる．
ほかの人の発表回に備える逆質問のように，ユーザーが別のファイルに決めているものはそれに従い，そのファイルに「## 想定質問」の見出しを置く．

## 参照ファイルとスクリプトの場所

プラグインとして導入した場合は次の位置にある．

- `${CLAUDE_PLUGIN_ROOT}/skills/rinkou-qa/references/`
- `${CLAUDE_PLUGIN_ROOT}/skills/rinkou-qa/scripts/`
- `${CLAUDE_PLUGIN_ROOT}/skills/rinkou-qa/examples/`

`~/.claude/skills/rinkou-qa/` へ直接置いた場合は，この SKILL.md と同じディレクトリの `references/`，`scripts/`，`examples/` を使う．以降のパスはスキルのディレクトリからの相対で書く．

## 手順

1. **読む**
   - メモリに輪講や課題のルール（研究室の書式，添削で受けた指摘，ノートの置き場所）があれば，最初に読む
   - 対象の資料（tex と PDF）．式番号・図番号と，それが何ページの上端か下端かを控える．必要なら原著も見る
   - 対象のノート全体．原稿，時間配分，解説に加えて，ユーザーが書き込んだメモ（「逆質問」，添削の書き込みなど）を拾う
   - 関係するノートの既存の想定質問．課題原稿なら，元になった発表原稿の想定質問を読み，答えを食い違わせない
2. **洗い出す**：[references/checklist.md](references/checklist.md) の観点を，課題ごと・節ごとにすべて当てる．
3. **元データを書く**：作業用の一時ディレクトリに元データのテキストファイルを作る．書式は [references/source-format.md](references/source-format.md)，実例は [examples/Kadai20261013_source.txt](examples/Kadai20261013_source.txt)．
   - ノートに想定質問の節がすでにあるなら，先にそれを元データに起こしてから足す．並べ替えると番号が変わる．そのため，本文や解説で「想定質問 B6」のように番号を参照している箇所は `grep` で確かめる．
4. **検算**：新しく書いた式と数値は sympy などで計算し直す．
5. **組み立てる**
   ```bash
   python3 -I scripts/build_qa.py 元データ.txt ノート.md --dry-run   # 節だけを標準出力に出して確かめる
   python3 -I scripts/build_qa.py 元データ.txt ノート.md             # 差し替える
   ```
   差し替えるときは，ノートと同じフォルダに `ノート.md.bak_YYYYMMDD` を自動で作る．問数の集計と警告は標準エラーに出る．
6. **確かめる**
   - エラーと警告がない（ドル記号の数が奇数，未定義の参照，書式違い，`` `` ``，最優先の数）
   - 「## 想定質問」より前と次の見出しより後が変わっていない（バックアップと `diff`）
   - ノート全体で `$$` の数が偶数．番号で参照している箇所が正しい
7. **メモリを更新**：輪講のメモリがあれば，ノート名と問数を追記する．
8. **報告**：結論を先に，です・ます調で書く．入れるものは次のとおり．
   - 総数，★の数，分類ごとの問数と主な内容（表）
   - 最優先の問い．新しく立てた論点
   - 検算したこと
   - **本人に確認してほしいこと**：推測で書いた答え，資料の弱点で突かれやすい所（記号の二重の意味など）
   - 変えていない所，気づいたが頼まれていない直し

## 節の型（上から順に）

1. 説明文：対象の資料，全問数，更新日，関係するノートへのリンク
2. **使い方**：★の意味，答え方（結論1文＋理由1〜2文），どこの質問かわからないときの確認の仕方，範囲外は広げない，表記の指摘は認める，分類の一覧
3. **本番前にこれだけは声に出して答える（最優先）**：表（番号｜質問）
4. **難易度別の索引**：レベル1〜3の説明と，表（分類｜問数｜レベル1｜レベル2｜レベル3｜★）
5. **練習の順番**：最優先 → 一問一答と前提知識 → 課題ごとの★ → 表記 → 発展と数値
6. 分類ごとの全問：`**A1．★質問**` の次の行から答え
7. **M. 答えに詰まったときの返し方**：確認する，結論だけ先に言う，式に戻る，範囲外は持ち帰る，指摘は認める，自作の図を突かれたとき

1〜2は `%head`，5は `%practice`，7は `%tail` に書く．3，4，6はスクリプトが作る．

## 注意

- **既存の節が手で作った独自の形**（論点別の最優先の表，答え方の型の表など）なら，スクリプトで丸ごと置き換えない．置き換えるなら，先に全問を元データに起こし，独自の表は `%head` か `%practice` に移す．数問足すだけなら，ノートを直接編集して索引の表も直す．
- 数を増やすために言い換えただけの質問は作らない．
- 新しいノートを作るときは，先にユーザーに確認する．既存ノートの節の差し替えは依頼の範囲に入る．
- 原稿や資料の本文は，頼まれない限り変えない．気づいた点は報告に書く．
