# 輪講の発表準備ノートを作る

輪講の準備ノートは4種類ある．まず，どれを作るかを決めてから，対応する参照ファイルを読む．

| 作るもの | 中身 | 読むもの |
|---|---|---|
| 自分の**発表原稿** | 担当範囲を発表する回の時間配分，やさしい言い換え，原稿，時間調整，想定質問，式・図・用語の解説 | [references/own-talk.md](references/own-talk.md) |
| 自分の**課題原稿** | 質疑で宿題になった課題を説明する回の時間配分，発表時の注意，記号の読み方，原稿，時間調整，想定質問，数学の解説 | [references/own-talk.md](references/own-talk.md) |
| ほかの人の回の**解説・質問**と**逆質問**，**回のメモ** | 資料の解説，その人に聞く質問，司会から来る逆質問への答え，自分用のメモ | [references/peer-notes.md](references/peer-notes.md) |
| **想定質問**（上のどのノートにも入る） | 最優先の表，難易度別の索引，分類ごとの全問，一問一答，詰まったときの返し方 | このファイルの「想定質問の作り方」 |

表：作るノートと参照ファイル．

## 呼び出し方とファイルの受け取り

`/rinkou-qa` と呼んでから，次のメッセージで資料やノートを添付する使い方を想定している．呼び出しと同じメッセージに添付や指示があってもよい．

1. **対象がまだないとき**（指示も添付もない）：作業を始めない．作れるノートを2〜3行で示し，資料（PDF，tex）や対象のノート（.md）を添付するよう頼んで待つ．
2. **添付を受け取ったら**，ファイル名と中身から作るノートを決める．判断がつかないときだけ確認する．

   | 添付されたもの | 作るノート |
   |---|---|
   | 自分の名前（メモリにある表記）が入った担当範囲の資料（`{範囲}_{名+姓}.pdf`） | 発表原稿 |
   | 自分の課題資料（`Kadai{日付}_{名+姓}.pdf` など） | 課題原稿 |
   | ほかの人の名前が入った資料 | 解説・質問，逆質問，回のメモ |
   | 既存のノート（.md）だけ | そのノートの想定質問を増やす．頼まれれば足りない節を補う |
   | 添削の PDF（`tensaku*`，`*_Tennsaku*` など），旧版の資料 | 表記の指摘の確認と，版の比較に使う |
   | 原著のスキャン | 照合に使う |

   表：添付されたファイルと作るノート．

   - 先に，ユーザーの運用ルール（メモリ，運用ルールのノート，親ノートの一覧）を読む．同じ資料のノートがすでにあれば，新しく作らずにそれを更新する案にする．
   - **人の名前をファイル名のローマ字から推測しない**（TaigaBan から漢字は決まらない）．親ノートやメモリの人の一覧で確かめ，なければ確認の中で聞く．
   - ファイル名の既定は，解説・質問が `{範囲}_{名+姓}_解説・質問.md`，逆質問が `{範囲}_{名+姓}_逆質問.md`，回のメモが `第N回輪講_M_D.md`（N は開催順，M_D は開催日）．運用ルールがあればそちらに従う．

3. **書き始める前に1回だけ確認する**：作るノートの種類，ファイル名と置き場所（運用ルールに沿った案），形式（これまでと同じ Markdown），使う資料を1つの一覧にまとめて示す．質問を何回にも分けない．既存のノートの節を差し替えるだけなら確認は要らない．
4. **添付の届き方**：パスとして届く場合（ターミナルへのドラッグ，`@` での指定）と，中身だけが届く場合がある．
   - パスがあれば，スクリプトにはそのパスを引数で渡す．ダウンロードしたファイルのフォルダの中でコードを実行しない．
   - 中身だけでパスがなければ，ファイル名で `~/Downloads` などを探す．見つからなければ，読み取ったテキストを一時ファイルに保存し，`check_coverage.py` には `--text` で渡す．

## 共通の決まり

どのノートにも共通する決まりは次のとおり．

- **ユーザーの運用ルールを先に読む**．メモリに輪講や課題のルール（研究室の書式，添削で受けた指摘，ノートの置き場所とファイル名）や，運用ルールのノートがあれば，それに従う．このスキルの置き場所の例より優先する．
- **原著と照合し，数値は検算する**．式の意味を完璧に調べ，図を見て気づいたこと（原著の図は概略図で，式と合わない所がある）も調べる．
- **冗長にしない**．必要十分な内容にし，水増しはしない．
- **ユーザーがノートに書き込んだメモ**（添削，「逆質問」，聞かれそうなこと）は消さずに残し，内容を反映する．
- 新しいノートを作るときは，ファイル名と置き場所をユーザーに確認する．既存ノートの節の差し替えは依頼の範囲に入る．
- 原稿や資料の本文は，頼まれない限り変えない．気づいた点は報告に書く．

## 参照ファイルとスクリプトの場所

プラグインとして導入した場合は `${CLAUDE_PLUGIN_ROOT}/skills/rinkou-qa/` の下にある．`~/.claude/skills/rinkou-qa/` へ直接置いた場合は，この SKILL.md と同じディレクトリを使う．以降のパスはスキルのディレクトリからの相対で書く．

- `references/`：作り方（[own-talk.md](references/own-talk.md)，[peer-notes.md](references/peer-notes.md)，[checklist.md](references/checklist.md)，[source-format.md](references/source-format.md)）
- `templates/`：ノートのひな形（[own-talk.md](templates/own-talk.md)，[assignment-talk.md](templates/assignment-talk.md)，[peer-notes.md](templates/peer-notes.md)，[peer-reverse-qa_source.txt](templates/peer-reverse-qa_source.txt)，[session-memo.md](templates/session-memo.md)）
- `scripts/build_qa.py`：元データから「## 想定質問」節を組み立てて差し替える
- `scripts/check_coverage.py`：資料の PDF に出てくる式・図・表の番号が，ノートの見出しにすべてあるかを調べる
- `examples/`：想定質問の元データの実例（[Kadai20261013_source.txt](examples/Kadai20261013_source.txt)，268問）

## 想定質問の作り方

発表原稿・課題原稿の「## 想定質問」節や，逆質問ファイルに，資料のどこを突かれても詰まらないだけの質問と答えを入れる．
作者の実績は，担当範囲の発表原稿で344問，質疑4問の課題原稿で268問（★59，最優先20），ほかの人の回の逆質問で163問．
自分の発表原稿・課題原稿では，想定質問だけの別ノートは作らず，原稿ノートの節にまとめる．逆質問はユーザーの運用に合わせて別ファイルにし，そのファイルに「## 想定質問」の見出しを置く．

1. **読む**
   - 対象の資料（tex と PDF）．式番号・図番号と，それが何ページの上端か下端かを控える．必要なら原著も見る
   - 対象のノート全体と，ユーザーの書き込み
   - 関係するノートの既存の想定質問．課題原稿なら元になった発表原稿の想定質問，逆質問なら解説・質問ファイルを読み，答えを食い違わせない
2. **洗い出す**：[references/checklist.md](references/checklist.md) の観点を，課題ごと・節ごとにすべて当てる．分類の決まりも同じファイルにある．
3. **元データを書く**：作業用の一時ディレクトリに元データのテキストファイルを作る．書式は [references/source-format.md](references/source-format.md)．逆質問なら [templates/peer-reverse-qa_source.txt](templates/peer-reverse-qa_source.txt) から始める．
   - ノートに想定質問の節がすでにあるなら，先にそれを元データに起こしてから足す．並べ替えると番号が変わる．そのため，本文や解説で「想定質問 B6」のように番号を参照している箇所は `grep` で確かめる．
4. **検算**：新しく書いた式と数値は sympy などで計算し直す．
5. **組み立てる**
   ```bash
   python3 -I scripts/build_qa.py 元データ.txt ノート.md --dry-run   # 節だけを標準出力に出して確かめる
   python3 -I scripts/build_qa.py 元データ.txt ノート.md             # 差し替える
   ```
   差し替えるときは，ノートと同じフォルダに `ノート.md.bak_YYYYMMDD` を自動で作る．問数の集計と警告は標準エラーに出る．
6. **確かめる**
   - エラーと警告がない（ドル記号の数が奇数，未定義の参照，書式違い，`` `` ``，最優先の数）
   - 「## 想定質問」より前と次の見出しより後が変わっていない（バックアップと `diff`）
   - ノート全体で `$$` の数が偶数．番号で参照している箇所が正しい
7. **メモリを更新**：輪講のメモリがあれば，ノート名と問数を追記する．
8. **報告**：結論を先に，です・ます調で書く．入れるものは次のとおり．
   - 総数，★の数，分類ごとの問数と主な内容（表）
   - 最優先の問い．新しく立てた論点
   - 検算したこと
   - **本人に確認してほしいこと**：推測で書いた答え，資料の弱点で突かれやすい所（記号の二重の意味など）
   - 変えていない所，気づいたが頼まれていない直し

### 節の型（上から順に）

1. 説明文：対象の資料，全問数，更新日，関係するノートへのリンク
2. **使い方**：★の意味，答え方（結論1文＋理由1〜2文），どこの質問かわからないときの確認の仕方，範囲外は広げない，表記の指摘は認める，分類の一覧
3. **本番前にこれだけは声に出して答える（最優先）**：表（番号｜質問）
4. **難易度別の索引**：レベル1〜3の説明と，表（分類｜問数｜レベル1｜レベル2｜レベル3｜★）
5. **練習の順番**（と，必要なら難易度別の答え方の型）
6. 分類ごとの全問：`**A1．★質問**` の次の行から答え
7. **M. 答えに詰まったときの返し方**

1〜2は `%head`，5は `%practice`，7は `%tail` に書く．3，4，6はスクリプトが作る．

**既存の節が手で作った独自の形**（論点別の最優先の表など）なら，スクリプトで丸ごと置き換えない．置き換えるなら，先に全問を元データに起こし，独自の表は `%head` か `%practice` に移す．数問足すだけなら，ノートを直接編集して索引の表も直す．

## 解説の網羅を確かめる

発表原稿の「式の解説」「図の解説」と，ほかの人の回の解説・質問ファイルは，資料に出てくる**すべての式と図**を見出しに立てる．書き終えたら次で確かめる．

```bash
python3 -I scripts/check_coverage.py 資料.pdf ノート.md
```

- 見出しにない番号があれば一覧を出して終了コード1で終わる．資料が参照しているだけの前の節の式（例：sinc 関数の定義式）も見出しを立てるのが原則．対象外にするものは `--ignore 1.38` や `--ignore 図1.2` で外す．
- `pdftotext`（Poppler）が要る．ない場合は PDF を読んでテキストに保存し，`--text` で渡す．
- 課題原稿の「数学的理解のための解説」は，資料の式変形の補足なので対象外．
