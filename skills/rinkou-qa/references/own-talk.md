# 自分の発表原稿・課題原稿の作り方

自分が発表するときのノートは2種類ある．

| ノート | いつ使うか | ひな形 |
|---|---|---|
| 発表原稿 `発表原稿_{範囲}.md` | 担当範囲（原著の節）を発表する回 | [../templates/own-talk.md](../templates/own-talk.md) |
| 課題原稿 `課題原稿_{内容}.md` | 質疑で答えられず宿題（課題）になった問いを，課題資料で説明する回 | [../templates/assignment-talk.md](../templates/assignment-talk.md) |

表：自分の発表のノートの種類．

置き場所とファイル名は，ユーザーの運用ルール（ノートやメモリ）があればそれに従う．
どちらも1つのノートに「話す原稿」と「質疑に耐えるための下地（想定質問，式・図・用語の解説）」をまとめる．

## 共通の進め方

1. 資料（tex と PDF）と原著を読み，式番号・図番号と，それが資料の何ページのどこ（上端・下端）にあるかを控える．
2. **式の意味を完璧に調べ，図を見て気づいたことも調べる**（原著の図は概略図で，式と合わない所がある）．数値は sympy などで検算する．
3. 原稿は1分あたり約330字で見積もり，節ごとの時刻を振る．
4. 想定質問は SKILL.md の手順で作る．
5. 発表原稿なら，`scripts/check_coverage.py 資料.pdf ノート.md` で，資料のすべての式・図に解説の見出しがあるかを確かめる．資料が参照しているだけの前の節の式も見出しを立てる（例：sinc 関数の定義式）．課題原稿の「数学的理解のための解説」は，資料の式変形の補足なので，すべての式をそろえなくてよい．
6. ユーザーがノートに書き込んだメモ（添削，「逆質問」，課題の候補）は消さずに残し，内容は想定質問や原稿に反映する．

**冗長にしない**．必要十分な内容にし，水増しはしない．聞かれていない補足は原稿に入れず，解説か想定質問に回す．

## 発表原稿の並び

1. **frontmatter**：tags（勉強，ゼミ，輪講，発表原稿），科目，発表範囲（原著のページ），目安時間，作成日
2. **時間配分**：表（時刻｜内容｜図・式）．節ごとに1行．
3. **資料を超簡単に言うと**：専門用語をできるだけ使わない言い換え．正確さより「何の話か」をつかむことを優先する．
   - **30秒版**：節の流れを5項目程度で．各項目の最後に「式では〜」を1つ添える．
   - **節ごとの言い換え**：節ごとに2〜4項目．最後に「**式で書くと**：」の項目を付ける．
   - **式を一言で**：表（式｜式の中身｜超簡単に言うと）．
   - **図を一言で**：表（図｜超簡単に言うと｜対応する式）．
   - **詰まったときに思い出すたとえ**：用語ごとに「たとえ．式では〜」．
4. **原稿**：節ごとの見出しに時刻を付ける（例：`### 1.6.1 インパルス応答（0:45-2:00）`）．です・ます調で，口で読む文にする．冒頭は「〇〇研究室，〇〇です．」と名乗ってから，前の節との位置づけを1〜2文で言う．
5. **時間調整用のメモ**：巻きたいとき（飛ばす文と短縮できる秒数），余ったとき（足す文）．
6. **想定質問**：rinkou-qa の型．輪講で実際に聞かれて宿題になった質問は R として先頭に置き，課題で答えた内容を口頭用に直す．
7. **式の解説（資料に出てくるすべての式）**：資料の順に，番号付きも番号なしも文中の式も．各式は `#### 式(1.45)　題` の見出しにし，次を書く．
   - **意味**，**なぜそうなるか**（導き方を段階に分けて），**読み取れること**，**身近な例・数値例**，**注意**
   - 節の最後に **式の早見表**（式｜内容｜一言で）．
8. **図の解説（資料に出てくるすべての図）**：最初に **図の流れ** の表（図｜領域｜何の図か｜言いたいこと）．各図は `### 図1.14　題` の見出しにし，**基本情報**（資料と原著の位置，原題，重ねた日本語ラベル，本文での参照），**何を表しているか**，**図の要素**，**読み取れること**，**式との対応**，**注意（概略図）**，**関連する質問** を書く．
9. **用語解説（資料に出てくる語をすべて）**：節ごと．主要な語は **一言で**（「〇〇とは何ですか」と聞かれたらまず言う），**詳しく**，**たとえ・例**，**資料では**，**関連**（想定質問の番号）．資料に出ないが質疑で出やすい語も入れる．最後に **記号の一覧**（記号｜読み方｜意味｜単位）．
10. **関連**：親ノート，資料のパス，課題資料．

## 課題原稿の並び

1. **frontmatter**：課題範囲（原著のページと節），目安時間，作成日，発表日
2. **冒頭**：課題資料のパスとページ数，どの回の質疑の課題か．
3. **時間配分**：表（時刻｜内容｜資料のページ｜式・図）．表の下に，図が何ページの上端・下端にあるかを書く．
4. **発表時の注意（これまでの指摘）**：下の「話し方の決まり」から，その回に効くものを並べる．
5. **記号の読み方**：表（記号｜読み｜意味）．口で読むときに迷う記号をすべて．
6. **原稿**：
   - 導入は課題の数と中身だけ（「〇つの課題を説明します．1ページの一覧のとおり〜」）．前の発表の内容を説明し直さない．
   - 各課題は資料と同じく「どんな課題か → 答え（理由は〜ためです）→ 説明 → 以上より〜」．答えを最後まで引っぱらない．
   - 図・式は「3ページ下の図1.13(b)」「1ページの式(1.63)」とページ付きで言う．課題資料は図が本文と離れたページの上下端にあるため．
7. **時間調整用のメモ**：約330字/分での見積もり，巻きたいとき（課題ごとに飛ばす文と秒数），余ったとき（資料にあって原稿で省いた文）．
8. **想定質問**：rinkou-qa の型（Z 課題全体，A〜 課題ごと，F 図，H 表記，P，J，L，N，Q，M）．
9. **数学的理解のための解説**：資料の式変形を1行ずつ追えるように補足する．発表で話す内容ではなく，質疑に耐えるための下地．番号付きの小見出し（`### 1. 式(1.63)　分圧から伝達関数へ`）．
10. **関連**：親ノート，元になった発表原稿（R の番号），前回の課題原稿，課題資料と自作の図のソースのパス．

## 話し方の決まり（作者が輪講で受けた指摘）

ユーザーのメモリや運用ルールに別の指摘があれば，そちらを優先する．

- 式は読み上げない．「式(1.○○)のとおり」と番号を言い，その式が何を表すかを説明する．
- 図は「（○ページの）図1.○○をご覧ください」と言って一呼吸置く．ポインターは回さず，指す．
- 導入はタイトルと位置づけだけ．前の担当の範囲の内容には触れない．
- まとめは要らない．例題は本発表では触れなくてよい（聞かれたら答える）．
- 訳語で読む．「無歪み」ではなく「歪みのない」，カタカナ語ではなく資料の訳語（白色雑音など）．
- 略語は口頭でも初出で正式名を言ってから使う（「理想低域通過フィルタ，LPF」）．記号も初出で何を指すかを言う（「振幅特性 |H(f)|」）．
- 時刻（点）と時間（長さ）を言い分ける．
- 聞かれていない補足は口頭でも足さない．聞かれたら答える．
- 冗長にせず，必要十分に話す．
