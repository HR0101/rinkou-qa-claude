# 想定質問の洗い出しと答え方

「できる限り詰める」とは，資料のどの文・式・図・記号を指されても詰まらない状態にすること．
数を増やすために言い換えただけの質問は作らない（水増しはしない）．

## 分類（接頭辞）の決まり

### 課題原稿（発表の質疑で宿題になった問いへの回答など）

| 接頭辞 | 分類 | 中身 |
|---|---|---|
| Z | 課題全体 | 全問の答えを一言ずつ，課題の出どころ，並べ順，範囲欄，式番号の振り方，添削でどう直したか，参考にしたもの |
| A，B，C，D… | 課題ごと（題名は「課題1.1　〜」） | 1課題に40〜50問が目安 |
| F | 図 | 原著の図か自作か，線・軸・目盛り，載せなかった図の理由 |
| H | 表記・式番号・文体 | 同じ記号の二重の意味，略語のスペルアウト，見出しと本文の値の書き方 |
| P | 前提知識（超基礎） | 用語の定義を10秒で |
| J | 他の節・章とのつながり | |
| L | 発展的・意地悪な質問 | 資料の範囲外．聞かれたときだけ答える |
| N | 数値で聞かれたときの計算 | 代表的な部品の値などで計算した値 |
| Q | 一問一答（10秒で答える） | 質問と答えが1文ずつ |
| M | 答えに詰まったときの返し方 | `%tail` に書く（番号なし） |

### 発表原稿（担当範囲の発表）

R（輪講で実際に聞かれた宿題），A〜G（節ごと），H（図），I（訳語・表記・誤記の指摘），J（他の節），K（数学の基礎），P（前提知識），L（発展），N（数値），O（総括・自分の理解），Q（一問一答），M（詰まったとき）．
作者の発表原稿では，この分類で344問を作った．

- **R** は，輪講で答えられず宿題になった質問．課題で答えた内容を口頭用に直し，「口頭では」の答えと「**式で説明すると**」の項目を両方付ける．再び聞かれやすいので，最優先の表の先頭に置く．
- 発表の質疑の前にユーザーが書き込んだメモ（「振幅応答と位相応答の違いを聞かれるかも」など）は，その論点の質問番号を最優先の表にまとめる．

### 逆質問（ほかの人の発表回）

自分が質問しなかったときに司会から来る，内容理解の確認の質問．「〜について式(1.○○)を使って説明してください」の形が多い．

| 接頭辞 | 分類 | 中身 |
|---|---|---|
| Z | 全体 | 範囲全体と，各節・例題を一言で |
| A | 自分の担当とのつながり | 発表者の範囲が自分の担当の続きなら厚くする．自分に振られやすい |
| R | 実際に来た逆質問 | 輪講で実際に来た逆質問と答え．最優先の表の先頭に置き，同じ型の問いをほかの節にも立てる |
| B〜 | 節ごと（例題も1つの分類） | 式を使った説明，図の読み取り，「なぜ」，手順の各ステップの理由と順番 |
| H | 図 | 図の要素，概略図で式と合わない所 |
| P | 前提知識（超基礎） | |
| N | 数値で聞かれたときの計算 | |
| L | 発展的・意地悪な質問 | |
| Q | 一問一答（10秒で答える） | |
| M | 答えに詰まったときの返し方 | 自分の担当に引き寄せる，資料の誤りは原著の話として言う |

作者は163問（7ページ，★52，最優先21）と351問（11ページ，★58，最優先20）を作った．ファイルの作り方は [peer-notes.md](peer-notes.md)．

## 課題・節ごとに当てる観点

1. **一言で答える質問**：各課題・各節に必ず1つ．`★!` を付ける．
2. **元の質問の言い回し**：「図示して」「式で説明して」と言われた質問なら，「どの図・どの式が答えですか」を入れる．
3. **文ごと**：その文の「なぜ」「どういう意味」「具体的には」．資料の言い回し（「滑らかに増加，減少する」の増加はどこか，など）も突かれる．
4. **手順・処理の流れ**：番号付きの手順，ブロック図，「〜した後に〜する」「まず〜，次に〜」の文は，ステップごとに次の4つを立てる．司会の逆質問で突かれやすい（実例：「オーバーサンプリングをした後に再標本化する理由は？」．資料には手順が書いてあるだけで，理由は別のページにあった）．
   - なぜそのステップが要るのか（目的）
   - なぜその順番なのか（前後を入れ替えるとどうなるか）
   - そのステップを省くとどうなるか
   - そのステップの前後で何が変わるか（標本化率，帯域幅，データ量，振幅の分布など）
   - **対になる操作**（上げた率を下げる，圧縮した信号を伸長する，前置フィルタと後置フィルタ，標本化と復元）は，「なぜ戻すのか」「戻さないとどうなるか」を必ず聞く．
   - 手順の有無を比べる文（「オーバーサンプリングなしの3ステップ」と「ありの5ステップ」）は，「何が増えて何が減るか」を聞く．
5. **書かれていない理由**：「〜を選ぶ」「〜する必要がある」「〜を用いる」のように，理由を書かずに言い切った文には「なぜですか」を立てる．答えはほかのページの記述（費用，前の節の式など）から組み立て，資料にない推測なら答えにそう書く．`check_coverage.py --sentences` が〔手順〕〔理由なし〕の印を付ける．
6. **式ごと**：
   - 導出（どう出したか），各記号の意味と単位，符号の向き
   - 成り立つ条件，特別な値（0，∞，境界，$a+b=1$ のような特殊な場合）
   - 近似の条件（「$|f|$ が大きいとき」など），他の式との関係
   - 教科書の式か，課題で新しく立てた式か
7. **図ごと**：原著か自作か，軸・目盛り・線の種類（実線・破線・点線），負の周波数まで描く理由，原著の図が概略図で値がずれている所，その図を選んだ理由と載せなかった図．
8. **表記**：
   - 同じ記号が2つの意味で使われていないか（例：$\theta$ が偏角と遅れの量で符号が逆，$a$ が振幅と係数，$\tau$，$h(t)$）
   - 略語のスペルアウト，訳語の揺れ，見出しと本文の値の書き方（0.707 と $1/\sqrt2$）
   - ここは資料の弱点になりやすい．報告で「本番前に確認してほしいこと」に挙げる．
9. **反論・意地悪**：「〜ではないのですか」「〜と矛盾しませんか」「〜なら成り立つのでは」の形．境界の反例を自分で探す．
10. **前提知識**：その資料を読むのに要る用語（振幅特性，偏角，因果性，線形，時不変など）を全部．
11. **数値**：代表的な値で計算（遮断周波数，dB，比，時定数の何倍で消えるか）．すべて検算する．
12. **他の節・章**：前後の節，後の章（符号間干渉など）とのつながり．
13. **発展**：範囲外の有名な話（ペイリー・ウィーナーの条件，ギブス現象，ボード線図，雑音等価帯域幅など）．答えに「資料の範囲を超える話です」と書く．
14. **資料の作り方**：添削で直した点，構成・順番の理由，式番号の振り方，参考文献．

## 内容の深さ（資料を見ればわかる質問にしない）

答えが資料の1文にそのまま書いてある質問（「〇〇とは何ですか」「図の破線は何ですか」「〜は何年ですか」）は，**確認の質問**である．聞きやすいが，内容の理解は確かめられない．作者は，そういう質問ばかりで「元の資料を見たらわかるようなものばかり」と言われた．
司会の逆質問も，実際には資料に書いていない所（手順の理由など）を突いてくる．

質問の中心は，資料を見ただけでは答えが出ない**考えて答える質問**にする．資料1ページあたり5問以上．質問の頭に次の印を付ける（`check_coverage.py --min-deep-per-page` が数える）．

| 印 | 考え方 | 例 |
|---|---|---|
| 〔組み合わせ〕 | 資料の2か所以上をつなげないと答えが出ない | 「自動利得制御で利得を下げると，量子化の SNR はどうなりますか」（2.5.1.2 と式(2.20)） |
| 〔もし〕 | 条件やパラメータを変える | 「パルス幅 $T$ を $T_s$ まで広げると，どうなりますか」 |
| 〔比較〕 | 2つの方法・場合を比べる | 「PAM と PCM では，通信路雑音への強さはどう違いますか」 |
| 〔数値〕 | 資料にない値を計算する | 「SNR を 60 dB にするには，一様量子化で何ビット要りますか」 |
| 〔つながり〕 | 前の節，前の担当，自分の担当，後の章とつなげる | 「符号間干渉を，1.6 のインパルス応答の言葉で説明すると何ですか」 |
| 〔理由〕 | 資料に書かれていない理由，手順の目的と順番 | 「オーバーサンプリングをした後に，標本化率を下げるのはなぜですか」 |
| 〔限界〕 | 成り立たない場合，代償，実際との違い | 「エイリアシングが起きた信号を，後から完全に元に戻せますか」 |
| 〔前提〕 | 式や議論がどこで何を仮定しているか | 「式(2.8) の導出で，帯域制限はどこで使っていますか」 |

表：考えて答える質問の印．

- **見分け方**：答えを書いてから，資料の1文にそのまま書いてあるかを見る．書いてあれば確認の質問．
- **確認の質問を考える質問に変える**：同じ文に，別の所を組み合わせる，条件を変える，比べる，数値を入れる，前の節とつなげる．例：「量子化雑音とは何ですか」（確認）→「量子化雑音を減らそうとレベル数を増やすと，飽和は起きやすくなりますか」（〔もし〕）．
- **聞きやすさは言い回しで保つ**：考える質問でも，1文で短く，【ページ，場所】で指す所をはっきりさせる．内容を浅くして聞きやすくしない．
- 答えには根拠（どのページとどのページを組み合わせたか）を書く．資料にない推測なら，そう書く．
- 発表者への質問では，考えて答える質問を「6. 質問」の先頭（6-0）に置き，使い分けのめやすでも先に勧める．逆質問では分類 K（考えて答える質問）にまとめ，★の2問ほどを最優先の表に入れる．

## 問数の目安

「できる限り詰める」は，次の下限に届いてからが出発点である．作者は，逆質問を1回目に1ページ約15問で作って「少ない」と言われ，1ページ約32問（11ページで351問）に増やした．
発表者への質問は，理由や式を突っ込む難しい問いだけで作ったら「難しくて質問しにくい」と言われ，語の意味や図の読み方を確かめるだけの易しい問いを足した．すると今度は「→ はい で答えられるものばかり」と言われ，「何ですか」「なぜですか」「いくらですか」と答えを説明してもらう問いをレベルごとに足した（7ページで203問，うち確認の問い53問，説明の問い73問）．

| 作るもの | 目安（下限） | 作者の実績 |
|---|---|---|
| 逆質問（ほかの人の回） | 資料1ページあたり35問，式1つに7問，図1つに8問，各レベル1割以上，考えて答える質問1ページ5問 | 7ページで163問と354問，11ページで407問（考えて答える質問 35問，55問） |
| 自分の発表原稿の想定質問 | 資料1ページあたり50問，式1つに7問，図1つに8問，各レベル1割以上，考えて答える質問1ページ5問 | 約8ページで344問 |
| 自分の課題原稿の想定質問 | 1課題あたり80問（共通の Z，P，Q，L を除く），各レベル1割以上 | 4課題で268問，1課題で145問 |
| 発表者への質問（解説・質問） | 資料1ページあたり15問（表記の指摘を含む），式・図それぞれに2問，各レベル1割以上，レベル1〜2で2割以上，答えを説明してもらう質問4割以上，考えて答える質問1ページ5問 | 7ページで238問（考えて答える質問35問），11ページで224問（同55問） |

表：問数の目安．

- 「式に触れる問」は，質問か答えにその式番号（式(2.5) など）が出てくる問を数える．範囲（式(2.11)〜(2.13)）は間の番号すべてに数える．
- `scripts/check_coverage.py 資料.pdf ノート.md --qa 元データ.txt` で，総数と，目安に届かない式・図，1割に届かないレベルを一覧にできる．`--min-deep-per-page 5` で考えて答える質問（印付き）の数を調べる．発表者への質問は `--min-easy-share 0.2` でレベル1〜2の割合を，`--min-open-share 0.4` で答えを説明してもらう質問（想定回答の「→」が「はい」で始まらない質問）の割合を調べる．
- レベルは，元データなら `@レベル`（先頭に `%levels 5`），解説・質問ファイルなら「6. 質問」の小見出しの「レベルN」から数える．表記の指摘はレベルなしとして数える．
- 目安に届かないまま報告しない．報告には目安との比較とレベルごとの問数を書く．

## 足りないときの増やし方（水増しにしない）

同じ問いの言い換えは数えない．**まだ問いを立てていない対象**か，**まだ立てていないレベル**を探して足す．次の順に探すと抜けが見つかりやすい．

0. **レベルのはしご**：同じ文・式・図に，レベル1〜5の問いを1つずつ立てる．聞いていることが段階ごとに違うので，言い換えにならない．

   | レベル | 文に立てる問い | 式に立てる問い | 図に立てる問い |
   |---|---|---|---|
   | 1 | 「〇〇とは〜のことですね」 | 「$x$ は何を表していますか」 | 「図○は何の図ですか」 |
   | 2 | 「つまり〜ということですね」（言い換え） | 「式(N)をことばで言うと〜ですね」 | 「横軸・破線は何ですか」 |
   | 3 | 「なぜ〜なのですか」 | 「なぜこの形になるのですか」 | 「この図から何がいえますか」 |
   | 4 | 「前の節の〜とどうつながりますか」 | 「導き方」「数値を入れると」 | 「図から値を読むといくらですか」 |
   | 5 | 「〜のときも成り立ちますか」 | 「境界・極限ではどうなりますか」 | 「式と合わない所はありますか」 |

   表：レベルのはしごの例．

   発表者への質問では，同じ段に**確認の形**（「〜ですね」「〜という理解でよいですか」→ はい）と**説明の形**（「何ですか」「なぜですか」「いくらですか」→ 説明）の両方を立てられる．確認の形だけで数を増やさず，説明の形を4割以上にする．

1. **文**：`check_coverage.py --sentences` で書き出した文を上から見て，問いのない文に「何を言っているか」「なぜか」「具体的には」を立てる．
2. **式**：式1つにつき，次の7種類を1問ずつ．
   - 各記号の読み方と意味，単位（レベル1）
   - 式をことばで言うと何か（レベル2）
   - 「式(N)を使って〜を説明してください」（逆質問でいちばん多い形．レベル3）
   - 導き方（前の式からの1行ずつの変形，使った性質．レベル4）
   - 数値例（代表的な値を入れる．レベル4）
   - ほかの式との関係（どの式に代入されるか，どの式の特別な場合か．レベル4）
   - 特別な値（$n=0$ の項，等号の場合，0や∞，パラメータを極端にした場合．レベル5）
3. **図**：図1つにつき，次の8種類を1問ずつ．
   - 何を表している図か，どのページのどこにあるか（レベル1）
   - (a)(b)… の各パネル（レベル2）
   - 軸と目盛り（記号の意味．レベル2）
   - 線の種類（実線，破線，斜線，矢印の高さ．レベル2）
   - 図から読み取れること（レベル3）
   - 対応する式（レベル3）
   - 図から値を読む，式で計算した値と比べる（レベル4）
   - 概略図で式と合わない所，ほかの図との違い（レベル5）
4. **語と記号**：資料に出てくる語すべてに P（「〇〇とは何ですか」），記号すべてに Q（「〇〇は？」）．
5. **数値**：資料の数値すべてを計算し直す問いと，パラメータを変えた問い（代表的な値で）．
6. **つながり**：前後の節，前の担当者の範囲，自分の担当（自分が説明した式・図），後の章．
7. **反論・境界**：「〜ではないのですか」「〜のときはどうなりますか」．条件の等号，極限，例外．
8. **手順**：`check_coverage.py --sentences` で〔手順〕の付いた文のステップごとに「なぜ要るか」「なぜこの順か」「省くとどうなるか」「前後で何が変わるか」を，〔理由なし〕の付いた文に「なぜですか」を立てる．対になる操作（上げる↔下げる，圧縮↔伸長）は「なぜ戻すのか」．
9. **考えて答える質問**：確認の質問（答えが資料に書いてある）を1つずつ見て，〔組み合わせ〕〔もし〕〔比較〕〔数値〕〔つながり〕〔理由〕〔限界〕〔前提〕のどれかに変えた問いを足す（上の「内容の深さ」）．

## レベルとフラグの付け方

難易度は5段階に分ける（元データの先頭に `%levels 5`）．各レベルを全問の1割以上にする．

- **レベル1（超基礎：言葉の確認）**：語や記号の意味，どこに書いてあるか．「はい」か一言で答えられるもの．
- **レベル2（基礎：読み取り）**：図の要素・軸，式の記号を読む，資料の文を言い換える．資料を指しながら1文で答えるもの．
- **レベル3（標準：理由）**：なぜそうなるか，式や図が何を言っているか．
- **レベル4（応用：式・数値・つながり）**：導き方，数値の計算，他の節や前の担当とのつながり，条件を変えたらどうなるか．
- **レベル5（発展：範囲外・反論・誤り）**：資料の範囲外，反例，境界，原著の誤り，資料の弱点．
- 1.2.0 までの3段階の元データ（`%levels` なし）は，レベル1（基礎）・2（標準）・3（発展）のまま組み立てられる．
- **★**：聞かれやすいもの．全体の2割程度（課題原稿は268問中59問）．
- **!（最優先）**：本番前に必ず声に出す15〜20問．各課題の「一言で」，いちばん突かれやすい論点（記号の符号の食い違いなど），元の質問の言い回しへの答えを入れる．

## 答えの書き方

- です・ます調，句読点は全角「，」「．」．
- **結論を1文 → 理由を1〜2文 → 資料の該当箇所**（「3ページの式(1.82)」のようにページ付き）．
- 式を求められたときのために，必要なら `- **式で説明すると**：` の行を足す．口頭では先に言葉で答える．
- 既存の想定質問と同じ内容は，答えを食い違わせず「発表原稿の C18」のように番号で示す．
- 範囲外の話は「資料の範囲を超える話です」と書き，自分から広げない．
- 表記の指摘は認めて「次から直します」．言い訳をしない．
- 資料からわからず推測で書いた答え（課題の並べ順の理由など）は，報告で本人に確認を頼む．
- Markdown の注意：`` `` `` と `''` は使わず「」にする．自分で書く表のセル内の `|` は `\vert` にする．
- 単語の意味を聞く質問（「〇〇とは何ですか」）は，用語解説の「一言で」と同じ答えにする．
